# UI 还原度（按需触发）

**触发条件**（满足任一即必生成视觉还原用例）：

- 本次改动有设计稿（Figma / Sketch / 飞书 / Lark 等）
- 本次改动是新视觉 / 新布局 / 新组件 / 新主题 / 改 design tokens
- 用户明确要求做视觉对比

**不满足触发条件时**：在 SKILL.md §7 用例清单的「⊘ 不生成」栏写"未涉及视觉改动 / 无设计稿，跳过 UI 还原度"。

## 用例维度（8 条横切轴）


| 维度               | 用例方向                                                     |
| ---------------- | -------------------------------------------------------- |
| **间距 / 布局**      | margin / padding / gap 对齐设计稿（DevTools 量取，不是"看着差不多"）      |
| **字体**           | 字号、字重、行高、字距、字体族；fallback 字体下不破坏视觉                        |
| **颜色**           | hex 精确（不是"颜色相近"）；暗色模式同样精确                                |
| **圆角 / 阴影 / 边框** | border-radius / box-shadow（含 inset / spread）/ border 按规范 |
| **图标 / 图形**      | 尺寸、颜色、位置；切图保真（svg vs png）                                |
| **交互态**          | hover / focus / active / disabled 视觉与设计稿一致               |
| **动画 / 过渡**      | 时长、缓动函数、起止状态；prefers-reduced-motion 是否禁用                 |
| **多视口**          | 每个断点的布局都对得上设计稿（不是"自适应没崩"，是"每个断点都对得上")                    |


## 模板层例外（与 SKILL.md §1(c) 模板复用原则一致）

复用稳定 `<Button>` `<FormField>` `<ToolPage>` 等组件 / 模板时：

- **组件本身的视觉默认按既往验证过的规范，不重测**
- 只测**实例特异的视觉点**（独有 hero 图、独有间距、独有色彩、独有徽标、独有插画）

新写组件 / 改 design tokens / 改 theme provider → **不享受模板层例外**，全量验证。

## 验证手段

- Figma 在浏览器里同窗对照（点 inspect 拿精确 px / 颜色）
- 截图工具叠层对比（PixelPerfect / Figma plugin / Chrome DevTools)
- DevTools 量取实际 px / 颜色 / 字号 / 阴影

## 输出格式

UI 还原度用例在用例清单里和功能用例混排，每条用 `[视觉]` 前缀标记，期望栏要给具体值（不是"看着对"）：

```
[视觉] hero 主标题字号｜期望：32px / 字重 600 / line-height 1.2，与 Figma node-12345 一致｜P0｜DevTools 量取
[视觉] CTA 按钮 hover 态背景｜期望：#3B82F6 → #2563EB（200ms ease-out），与设计稿一致｜P1｜Figma 对照
[视觉] 卡片间距｜期望：gap 16px（移动端）/ 24px（桌面），与 Figma node-67890 一致｜P0｜DevTools 量取
```

## 禁用语（视觉用例特有）

- "看着差不多" → 给精确值（px / hex / 时长 / 缓动）
- "颜色接近" → 用 hex 对比
- "样式 OK" → 改写为具体维度（间距 / 字体 / 颜色...）
