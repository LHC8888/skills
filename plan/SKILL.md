# Plan - 计划管理

## 概述

为用户创建和管理可追踪、可执行的计划。

## 使用流程

### 第一步:确认信息

创建计划前,必须向用户确认以下信息(用户已提供的可跳过):

| 信息 | 必须 | 说明 |
|------|------|------|
| 计划名称 | ✅ | 小写英文连字符,如 `daily-report-enhance` |
| 计划存放目录 | ✅ | 用户指定的目录路径,未指定则询问 |
| 一句话描述 | ✅ | 这个计划要做什么 |
| 背景 | ❌ | 为什么要做?不提供则不写 |
| 目标 | ❌ | 最终达成什么效果?不提供则不写 |
| 步骤拆分 | ❌ | 是否需要帮忙拆分步骤?默认询问 |

示例确认话术:
> 好的,我来帮你创建计划。确认一下:
> 1. 计划名叫什么?
> 2. 放在哪个目录?
> 3. 一句话描述下这个计划要做什么?

### 第二步:创建目录和文件

目录结构(`<base>` = 用户指定的计划存放目录):

```
<base>/
├── <计划名>/
│   ├── README.md          # 计划概览 + 进度
│   ├── DECISIONS.md       # 决策记录(按需创建)
│   └── action/
│       ├── 01-<步骤名>.md
│       ├── 02-<步骤名>.md
│       └── ...
└── README.md              # 计划索引(多个计划时自动维护)
```

### 第三步:维护计划

支持的操作:

- **创建计划** - 用户说"制定计划"/"做个计划"
- **更新进度** - 用户说"更新进度"/"计划做到哪了"
- **执行步骤** - 用户说"执行第 N 步"/"做第 N 步"
- **记录决策** - 用户说"记录决策"/"方案改了"
- **同步状态** - 用户说"同步状态" - 扫描 action checklist 自动更新 README

### 自动进度追踪

**执行步骤时,必须同步更新进度:**

1. 每完成一个动作 → 勾选 action 文件中的 `- [x]`
2. 勾选后 → 立即更新 README 中该步骤的"进度"列(如 `1/4` → `2/4`)
3. 该步骤全部勾选 → 步骤状态改为 ✅,更新"总进度"
4. 每次执行结束 → 在"进度日志"中记录当天进展

不需要用户说"更新进度",只要在执行过程中自动维护即可。进度日志在每次执行结束时追加。

## README.md 格式

```markdown
# <计划名>

> <一句话描述>

## 状态: 🟢 进行中 | 🟡 暂停 | ✅ 完成 | ❌ 放弃

## 总进度: 2/9 步完成

## 背景
(可选)

## 目标
(可选)

## 步骤

| # | 步骤 | 状态 | 优先级 | 进度 | 动作文件 |
|---|------|------|--------|------|----------|
| 01 | xxx | ✅ | 🟡 | 3/3 | [01-xxx.md](action/01-xxx.md) |
| 02 | xxx | 🔄 | 🔴 | 1/4 | [02-xxx.md](action/02-xxx.md) |
| 03 | xxx | ⬜ | 🟢 | 0/2 | [03-xxx.md](action/03-xxx.md) |

> 状态: ⬜ 待开始 | 🔄 进行中 | ✅ 完成 | ⏸️ 暂停 | ❌ 跳过
> 优先级: 🔴 关键路径 | 🟡 重要 | 🟢 可选

## 进度日志

### YYYY-MM-DD
- 完成了什么
- 遇到什么问题
- 下一步做什么
```

**字段说明:**
- **总进度**:已完成步骤数 / 总步骤数
- **状态**:⬜ 待开始 | 🔄 进行中 | ✅ 完成 | ⏸️ 暂停 | ❌ 跳过
- **优先级**:🔴 关键路径 | 🟡 重要 | 🟢 可选
- **进度**:该步骤 action 文件中已勾选数 / 总 checkbox 数

## Action 文件格式

```markdown
# <步骤名>

## 目标
这一步要达成什么?

## 优先级
🔴 关键路径 | 🟡 重要 | 🟢 可选

## 具体动作

- [ ] 动作1:具体描述
- [ ] 动作2:具体描述
- [ ] 动作3:具体描述

## 产出物
这一步完成后应该有什么文件/结果?

## 验证方式
怎么确认这一步做完了?
```

## DECISIONS.md 格式

方案变更、pivot、重要决策时记录:

```markdown
# 决策记录

## YYYY-MM-DD - <决策标题>
- **背景**: 为什么需要做这个决策?
- **选项**: 考虑了哪些方案?
- **决定**: 最终选了什么?
- **影响**: 对计划有什么影响?
```

## 进度同步规则

正常情况下进度随执行自动更新。用户说“同步状态”时作为兜底，全量扫描一次：

1. 扫描 `action/` 下所有 `.md` 文件
2. 统计每个文件中 `- [x]` 和 `- [ ]` 的数量
3. 更新 README 步骤表的“进度”列
4. 更新步骤状态：全部勾选 → ✅，部分勾选 → 🔄，全未勾选 → ⬜
5. 更新总进度：已 ✅ 的步骤数 / 总步骤数

## 命名规范

- 计划名:小写英文,连字符分隔
- 步骤文件:两位数字前缀,如 `01-xxx.md`、`02-xxx.md`
- 状态:⬜ 待开始 | 🔄 进行中 | ✅ 完成 | ⏸️ 暂停 | ❌ 跳过
